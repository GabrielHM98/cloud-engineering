# Step 2 — validate CompTox structures and join chemical functions

This extends the existing CPDat audit. The original audit and pinned source snapshot are unchanged. The new validator uses the exact columns in your CompTox export, validates the requested-ID join, and produces structure–role candidates with their supporting evidence.

| Outcome | Substances |
|---|---:|
| Requested IDs returned with matching identifiers | 100 |
| Accepted by this first structure and identifier policy | 51 |

The accepted records represent 51 unique canonical structures and 146 distinct structure–role pairs, supported by 2,649 source annotation records. Those evidence records are not independent training examples.

Of the 51 accepted records, 36 source InChIKeys match the recomputed Standard InChIKey exactly; 15 differ only at the standard/nonstandard flag. The policy records this precise exception instead of labelling it a structural conflict. Both original and recomputed keys are preserved. These are sample-specific findings, not a population-wide coverage estimate or classifier performance result.

The source CSV was not modified. `example-structure-input/comptox_sample.csv` is a byte-for-byte copy of the upload; `example-structure-output/` contains the actual results.

## Install the chemistry dependencies in WSL

The supplied dependency pins were tested with **Python 3.12 on Linux x86_64**. NumPy's pinned version requires Python 3.12 or newer. Check your interpreter before creating the environment:

```bash
cd ~/src/industrial-use-starter
python3 --version
```

For Python 3.12, create or activate this project's environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-structures.txt
```

If creating the environment reports that `ensurepip` is unavailable on Ubuntu, install `python3-venv` with apt, then repeat creation. Use this project's environment rather than changing the earlier MatterGen environment.

The three pinned packages are RDKit, NumPy, and Pillow. This validator uses RDKit's CPU chemistry routines. It does not require a CUDA installation.

## What the validator does

1. Verifies the pinned CPDat archive's size and checksums.
2. Requires explicit input, returned identifier, SMILES, and InChIKey columns in the CompTox CSV.
3. Checks every requested identifier using a left-join approach, including IDs absent from the export. It flags mismatched IDs, unexpected rows, and conflicting duplicate mappings.
4. Parses ordinary SMILES with RDKit and applies the versioned structure policy.
5. Compares the provided InChIKey with the one calculated from the structure. A single standard/nonstandard flag difference is recorded separately; other key differences are quarantined.
6. Creates a molecular identity from canonical isomeric SMILES, the full policy hash, and RDKit version. Identity is not derived by discarding stereochemistry or merging on InChIKey alone.
7. Joins retained CPDat annotations by DTXSID, following the original nonprovisional-ID and known-role policy.
8. Deduplicates structure–role pairs while preserving their original evidence records and source-substance identifiers.

## Structure policy

`structure_policy.json` documents the v1 behavior. This first scope accepts a single connected, carbon-containing structure with atoms drawn from H, C, N, O, F, P, S, Cl, Br, I.

- Preserve supplied stereochemistry, isotopes, and formal charges.
- Do not remove counterions, neutralize structures, merge tautomers, or invent missing stereochemistry.
- Route missing SMILES, multicomponent substances, extended notation, wildcard/query atoms, radicals, and unsupported elements to review.
- Preserve source QC levels and notes; this release imposes no QC-level cutoff.
- Require a source InChIKey and an accepted cross-check result.

The S/N InChIKey exception is tightly constrained: position 24 alone may differ, while both hash blocks, version, and protonation indicator must match. Other differences are not silently normalized away. See the [InChI Trust technical FAQ](https://www.inchi-trust.org/technical-faq/), section 13.1.

Some extended notations describe definite structures; their exclusion means this parser policy does not support them yet. Salts can also be valuable industrial chemicals, including surfactants. Preserve them for a later reviewed representation policy rather than transferring their labels onto a counterion-stripped molecule automatically.

RDKit acceptance checks the supplied graph under this policy. It does not prove the substance–structure assignment or its reported industrial function is correct. The available quality metadata remains important for further curation.

Changing normalization behavior requires corresponding code, tests, and a versioned policy. The validator refuses settings for transformations it has not implemented.

| File | Meaning |
|---|---|
| `data/processed/structure_sample/export_validation.csv` | Every exported CSV record, preserving original structure and key fields |

Outputs in these namespaces are replaced on reruns. Source inputs remain unchanged. The manifest records the validation time; the CompTox export does not embed a retrieval timestamp, so record the original download date and dashboard URL alongside the raw export separately.

## Next checkpoint

This confirms the structure-lookup and join route on the diagnostic sample. To complete feasibility:

1. Resolve all retained substance IDs using the two full-list batches from the first audit.
2. Validate the full exports using their complete requested-ID list and retain unresolved mappings.
3. Measure per-role structural coverage and family diversity on that larger dataset.
4. Decide whether and how to support salts and other important excluded categories.
5. Select a supported role set, then freeze molecular-family partitions for model comparison.

The sample command accepts one CSV at a time and defaults to the 100-ID sample. For the complete list, use the coordinated multi-export importer documented in `STEP3.md`. It reconciles overlapping exports and deduplicates molecular identities globally. Do not add independent batch reports together and call the sum unique molecular coverage.

No model has been trained by either audit step. Missing role annotations remain unknown. The eventual classifier will be evaluated on held-out chemical families under an explicit policy for incomplete labels.
